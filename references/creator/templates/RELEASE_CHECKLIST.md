# Release Checklist

- Product criteria and required runtime/device rows have retained outcomes.
- The source and lock match the built and tested artifact.
- Manifest, compatibility map, package version, tag plan, and assets agree.
- Current official directory policies and submission instructions were checked.
- License and notices cover the actual bundled third-party code.
- README disclosures match network, file, account, payment, and telemetry behavior.
- Screenshots and claims describe observed behavior and retain limitations.
- Previous tested assets and any needed data recovery copies are available.
- Data migrations and downgrade limitations are explicit.
- Support diagnostics exclude credentials and private note content.
- The owner has approved the concrete tag/push/publication/submission action.
- The actual external outcome is retained separately from local checks.

Approval is pending until explicitly supplied. Preparing a package is not a
published release, directory acceptance, or authorization to modify an active vault.
